# content-repo-readme SKILL

## 适用仓库类型

本 SKILL 适用于**纯内容仓库**：
- 文档 / SKILL / 知识笔记
- 配置文件
- 项目结构变更

不适用于代码项目（CLI 工具、库、Web 服务、前端项目等）。

---

## 文档结构

以下为完整结构。按需选择板块，**不要强求覆盖所有板块**——只保留与当前仓库相关的。

### 1. 项目简介

1-2 段话说明仓库的定位和内容范围。例如：

> 本仓库收录了 [主题/领域] 相关的技能定义（SKILL）、知识文档和配置文件，用于 [用途说明]。

### 2. 内容概览

用表格列出各模块/SKILL/文档的入口链接和简短说明：

| 模块 | 说明 |
|------|------|
| [模块名](路径) | 一句话说明内容 |
| [模块名](路径) | 一句话说明内容 |

- 如果仓库按目录组织，以目录为行
- 如果仓库是扁平的，以文件为行
- 不需要列出每个文件，只列入口级别

### 3. 目录结构

用树形图展示核心目录和文件的职责（如果仓库文件不多，与"内容概览"合并即可）：

```
repo-root/
├── skills/          # 技能定义
│   ├── skill-a/     # 技能 A 的完整定义
│   └── skill-b/     # 技能 B 的完整定义
├── docs/            # 知识文档
└── README.md        # 本文件
```

### 4. 快速导航

如果仓库包含关键入口文档，列出直达链接：

- [文档名称](路径) — 一句话说明
- [文档名称](路径) — 一句话说明

### 5. 维护指南（可选）

说明如何向此仓库添加/修改内容：

- 新增 SKILL 需要创建什么文件
- 目录命名规范
- 提交 message 规范（如使用 Conventional Commits）

### 6. 更新日志（可选——非必须板块）

如果用户要求或仓库已有更新日志习惯，列版本历史。

**如果用户未提供版本历史和变更内容，写"暂无版本记录"**。如果用户提供了部分版本但有空缺，只列出已提供的版本，空缺处标注"待补充"。

---

## 风格要求

- **语言**：中文
- **读者画像**：需要了解仓库内容结构的协作者或使用者
- **技术深度**：无需技术背景。纯内容仓库的 README 不涉及代码、运行时、API
- 避免使用 emoji
- 代码块使用 ```bash 或 ```text 标注语言

---

## 编造防范规则

以下板块在信息不足时必须执行兜底操作，**禁止自行编造**：

1. **内容概览**：如果 AI 无法从文件列表推断模块用途，写"文件清单见目录结构"，不编造功能说明
2. **更新日志**：用户未提供 → 写"暂无版本记录"。用户提供部分 → 只列提供的部分，空缺标"待补充"
3. **目录结构**：如果用户未提供目录结构且文件不在当前工作目录中，写"目录结构信息未提供"

**判断原则**：不确定的信息必须标注；完全推断的信息必须标注来源。

## 与通用 project-readme 的区别

| 板块 | 通用版（代码项目） | 本版（内容仓库） |
|------|------------------|----------------|
| 前置条件 | 列出操作系统、运行时 | ❌ 不适用 |
| 快速开始 | 3-5 步运行项目 | ❌ 不适用 |
| 安装/部署指南 | 包管理器/源码安装 | ❌ 不适用 |
| 使用示例 | CLI/代码片段示例 | ❌ 不适用 |
| 配置说明 | 可配置项表格 | ❌ 不适用 |
| API 文档 | 函数签名/接口端点 | ❌ 不适用 |
| 内容概览 | ❌ 不适用 | ✅ 模块/文件索引表 |
| 目录结构 | 可选 | ✅ 核心板块 |
| 维护指南 | 可选 | ✅ 推荐（内容库特有） |
| 快速导航 | ❌ 不适用 | ✅ 推荐 |

## 输出前自查清单

2. 编造规则是否遵守？（内容概览是否有 AI 凭空推断的功能说明？）
3. 是否有 emoji 混入？
